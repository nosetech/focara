# 要件定義

Focara(フォカラ)の要件定義です。以降の設計・issueの根拠となる文書で、元になっているコンセプトはInkdropの `allmytask-manager / Service-Concept` です。

## 1. コンセプト

| 項目 | 内容 |
| --- | --- |
| 一元管理 | 雑用、仕事の作業、人生の目標に対するアクションなど、人生のあらゆるタスクを一元管理する。AIと協力して効率よくタスクを進められるシステムとする |
| 日記的な記録 | これからやることだけでなく、やったことの記録も残す(日記) |
| モバイル重視 | モバイルでの使用が多くなるため、モバイルでの使いやすさを重視する。モバイルは新規タスクの作成・タスクの実行、デスクトップはタスクの整理を主な用途とする |
| タスクシュート | タスクの実行は着手する順番に1つずつ見せ、1つのタスクに集中させる |

## 2. 機能要件

### 2.1 タスクのステータス管理

タスクは次のステータスで管理する。

| ステータス | 内容 |
| --- | --- |
| inbox | 思いついたタスクをとりあえず保存する場所。未整理の状態 |
| 次にやる | 次に取り掛かるタスク |
| いつか | いつかやるタスク |
| 条件待ち | 日時・人からの連絡待ちなど、条件が満たされてから取り掛かるタスク |
| 習慣 | 繰り返し(習慣)の定義(親)。実行する日のタスク(子)の元になる。2.1.1参照 |

#### 2.1.1 習慣(親)と実行タスク(子)

習慣は「親(習慣の定義)」と「子(その日に実行するタスク)」に分けて扱う。

- 親は習慣として専用に管理し、習慣ページで一覧・作成・編集・一時停止・再開・削除する。タイトル・プロジェクト・優先度・作業時間見積もり・既定の枠(午前中/午後/夜)・繰り返しルール・開始日・終了条件を持つ。
- 子は通常のタスクとして扱い、どの親から生成されたかを保持する。3枠割り当て・カレンダー・実行画面に通常タスクと同様に表示され、習慣由来であることがバッジで分かる。
- 繰り返しルールは「毎日 / 曜日指定 / 月(日付指定) / 年(月日指定)」から選ぶ。
- 子は毎日の定期処理で、当日から数日先(既定14日)分を先に生成する。同じ親・同じ日付の子は重複して生成しない。
- 子の枠は親の既定値をコピーして生成し、子ごとに(この回だけ)枠・日付を変更できる。親の既定値を変更しても、生成済みの子は変わらない。
- 終了条件は「なし / 生成した子の累計回数 / 終了日」から選ぶ。累計回数は生成した子の数で数える。
- 一時停止中の親は子を新たに生成しない。再開すると、再開日以降の分から生成を再開する(停止中の日付は遡って生成しない)。
- 親を削除したとき、未完了の子は削除し、完了済みの子は実績(日記)として残す。
- 習慣ページには各親の直近7回の実施状況を表示する。親を基準に、その子の完了・未完了を集計する。
- 通常タスクの詳細には繰り返し設定を置かない。inbox整理では「習慣にする」操作で習慣の作成シートを開き、作成後に元のinboxタスクを削除する。

### 2.2 プロジェクト

- 複数のタスクをプロジェクトとしてまとめることができる。

### 2.3 実行画面(タスクシュート)

- 1日のタスクが積み上げられ、上から順に実行していく構成とする。
- 着手するタスクに注目させ、他のタスクはあまり目に入らないデザインにする。次のタスクが何か分かる程度の表示にとどめる。
- タスクをタップして、メモの記入やプロパティの設定ができる。
- タスクを横にスライドして後回しにできる。後回しにしたタスクは、現在の時間帯(午前・午後・夜)の最後に移動する。
- 思いついたタスクをinboxにとりあえず保存する機能を用意する。
- 1日の予定のタスクを一通り終えたら、終わっていないタスクをやるか、予定を変えるかを選べる。
- モバイルでの操作(新規タスク作成・実行)をやりやすいデザインにする。

### 2.4 整理画面

- 1日のタスクは、午前中・午後・夜のざっくり3つの枠に分けて「いつやるか」を決める。細かい時間は決めない。
- 打ち合わせなど日時が決まる予定も登録できる。
- 1日・1週間の予定をカレンダー表示できる。
- タスクの優先度・作業時間見積もりから、いつやるかをAIに提案してもらえる。
- デスクトップでの整理をやりやすいデザインにする。

### 2.5 AI連携

- AIはサーバーとなるローカルPC上で `claude -p`(Claude Code。Claude Pro/Maxなどのサブスクリプションプランを使用)を動作させて利用する。
- 将来的にCodexやAPIの利用にも拡張できる構成にする。
- 実装は producer-desk の実装を参考にする。

### 2.6 MCPサーバー

- MCPサーバーを用意し、AIを利用してGoogleカレンダーやテキストのタスク情報などから、このシステムにタスクを登録できるようにする。
- タスクの一元管理をやりやすくすることが目的である。

### 2.7 AIスキル

- タスクの種類によってAIのスキルを割り当て、分析や提案などを行えるようにする。
- スキルはプラグインとして配布できるようにする。

### 2.8 プロパティとグラフ

- タスクにプロパティを持たせ、そのプロパティを使ってグラフを描画できるようにする。
- 例: 体重・体脂肪率を測るタスクで記録した値をグラフ表示する。

## 3. 非機能要件

| 項目 | 内容 |
| --- | --- |
| システム形態 | 複数端末から操作するため、Webシステムとする |
| 対応端末 | モバイル・デスクトップなど複数の環境から操作でき、各端末で扱いやすいUIとする |
| テーマ | ライトモード・ダークモードを切り替えられる |
| 公開範囲 | LAN / Tailscale のみに公開する。インターネットには公開しない |
| AI実行環境 | ローカルPC上の `claude -p` を利用する。将来Codex・APIへ拡張できる構成にする |

## 4. スコープ外

- Googleカレンダーとの直接同期、およびそのためのOAuth連携は作らない。Googleカレンダーの予定は、MCPサーバー経由でAIがタスクとして登録することで取り込む(2.6参照)。
- インターネットへの公開は行わない(LAN / Tailscaleのみ)。

## 5. フェーズ計画

| Phase | 名称 | 概要 |
| --- | --- | --- |
| 0 | 基盤 | 要件・技術選定の文書化、開発環境・CI・画面デザイン |
| 1 | タスクコア | DB・タスクAPI・ステータス管理・プロジェクト・割り当て・繰り返し・メモ/プロパティ・完了記録 |
| 2 | 実行画面(タスクシュート) | 1タスク集中表示、完了・後回し、タスク詳細、クイック追加、PWA、LAN/Tailscale公開 |
| 3 | 整理画面 | inbox整理、3枠への割り当て、日時予定、カレンダー、プロジェクト画面、各種タスク一覧 |
| 4 | AI基盤 | ローカルPC上の `claude -p` によるAI実行基盤 |
| 5 | MCPサーバー | AIからのタスク登録 |
| 6 | AIスキル | タスク種別に応じたスキル割り当て・プラグイン配布 |
| 7 | プロパティ・グラフ | プロパティを使ったグラフ表示 |
| 8 | 実績ログ | やったことの記録(日記)の閲覧・活用 |

### MVP範囲

MVPは **Phase 0〜3** とする。AI連携・MCP・スキル・グラフ・実績ログ(Phase 4〜8)はMVP後に段階的に実装する。
