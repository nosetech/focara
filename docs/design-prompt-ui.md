# 画面デザインプロンプト(Claude Design 用)

Focara(フォカラ)の画面デザインを Claude Design で作成するためのプロンプトです。下記「プロンプト本文」をそのままコピペして使います。内容は [requirements.md](./requirements.md) と整合しています。

使い方: まず「共通」を貼り、続けて作りたい画面のセクション(A〜C)を貼る。画面ごとに分けて依頼してもよい。

---

## プロンプト本文

### 共通

```
あなたはUIデザイナーです。タスク管理Webアプリ「Focara(フォカラ)」の画面をデザインしてください。

# サービス概要
- 雑用・仕事・人生の目標のアクションなど、あらゆるタスクを一元管理する個人用Webアプリ。やったことの記録(日記)も残す。
- 思想は「タスクシュート」: タスクは着手する順に1つずつ見せ、1つのタスクに集中させる。
- モバイルは「新規タスクの作成・タスクの実行」、デスクトップは「タスクの整理」が主用途。

# デザイン要件
- レイアウト: モバイル(幅390px前後・片手親指操作)と、デスクトップ(幅1280px以上・一覧と詳細を並べる)の両方を作る。
- テーマ: ライトモード / ダークモードの両方を作り、切り替えられること。
- 全画面について、通常状態に加えて「空状態」「読み込み中」「エラー」の各状態を作る。
- 日本語UI。余計な装飾を避け、静かで集中しやすいトーンにする。
- 外部サービス(Googleカレンダー等)との直接同期UIは作らない。

# タスクのステータス(表示名と意味)
- inbox: 思いついたものをとりあえず保存する未整理の状態
- 次にやる: 次に取り掛かるタスク
- いつか: いつかやるタスク
- 条件待ち: 日時・人からの連絡待ちなど、条件が満たされてから取り掛かるタスク
- 習慣: 繰り返し(習慣)タスク
- 複数のタスクを「プロジェクト」としてまとめられる。

# 1日の枠
- 1日は「午前中」「午後」「夜」の3枠で「いつやるか」を決める。細かい時刻は決めない。
- 打ち合わせなど日時が決まる予定は、時刻つきの予定として別に登録できる。
```

### A. 実行画面(タスクシュート)— モバイル中心

```
# 実行画面(タスクシュート)
目的: 1日のタスクを上から順に実行する。モバイルでの操作を最優先にする。

## 構成
- 1日のタスクが縦に積み上がり、上から順に実行する。
- 「いま着手するタスク」を画面の主役にする(大きいタイトル、強いコントラスト、完了ボタンを親指が届く位置に配置)。
- それ以外のタスクは目立たせない(小さく・薄く)。ただし「次のタスクが何か」は分かる程度に見せる。
- 現在の枠(午前中/午後/夜)が分かる控えめな表示を置く。

## 操作
- タスクをタップ → タスク詳細(メモ・プロパティ)を開く。
- タスクを横にスワイプ → 後回し(スワイプ中に「後回し」の操作ヒントを表示。取り消しもできる)。
- 完了ボタン → 完了して次のタスクが主役になる(完了の軽いフィードバック)。
- 常設のクイック追加ボタン(FAB)で、inboxにタスクを追加できる。

## 表示項目(タスク1件)
タイトル、所属プロジェクト(あれば)、枠、予定時刻(予定タスクのみ)、優先度、作業時間見積もり、メモの有無、ステータス。

## 状態
- 通常: 着手中1件+次以降の積み上がり
- 1日の予定を終えた: 「終わっていないタスクをやる」か「予定を変える」かを選ぶ画面(未完了タスク一覧と2つの選択肢)
- 空(今日の予定なし): inboxの整理や予定追加への導線
- 読み込み中: スケルトン表示
- エラー: 再試行ボタンつきのメッセージ
```

### B. タスク詳細・クイック追加

```
# タスク詳細(メモ・プロパティ)
- モバイルはボトムシート(または全画面)、デスクトップは右サイドパネル。
- 項目: タイトル(編集)、ステータス、プロジェクト、日付・枠(午前中/午後/夜)、予定日時(任意)、優先度、作業時間見積もり、繰り返し(習慣)、条件待ちの条件、メモ(複数行・Markdown想定)、カスタムプロパティ(名前と値。例: 体重 62.5kg)。
- 操作: 完了、後回し、削除。変更は自動保存し、保存状態を小さく表示する。
- 状態: 通常 / 新規(空) / 読み込み中 / 保存エラー

# inbox クイック追加
- どの画面からも1タップで開ける。タイトル1行を入力して即保存できる最小UI(連続入力しやすく、保存後も入力欄が残る)。
- 状態: 入力中 / 保存中 / 保存成功(軽いトースト) / 保存エラー(入力内容を保持して再試行)
```

### C. 整理画面 — デスクトップ中心(モバイルでも閲覧可能に)

```
# 整理画面
目的: デスクトップで未整理のタスクを整え、「いつやるか」を決める。左にナビ、中央に一覧、右に詳細パネルを置く。

## 画面一覧
1. inbox整理: inboxのタスクを1件ずつ、または一括で「次にやる/いつか/条件待ち/習慣」に振り分け、プロジェクトや日付・枠を設定する。キーボード操作しやすくする。
2. 3枠割り当て: 日付ごとに「午前中/午後/夜」の3列(モバイルは縦3段)を並べ、未割り当てタスクをドラッグ&ドロップ(モバイルは枠を選ぶ操作)で割り当てる。枠ごとの見積時間合計を表示。
3. カレンダー(日): 3枠のタスクと、時刻つき予定(打ち合わせ等)を1日分表示する。
4. カレンダー(週): 7日分を並べ、枠ごとのタスク数・予定を俯瞰できる。日付へのドラッグで日付変更。
5. プロジェクト画面: プロジェクト一覧と、プロジェクト内のタスク一覧(ステータス別、進捗)。
6. 待ち一覧: 条件待ちタスクと待っている条件。条件が満たされたら「次にやる」に戻せる。
7. いつか一覧: いつかタスクの一覧と、「次にやる」へ昇格する操作。
8. 習慣一覧: 繰り返しタスクと繰り返しルール、直近の実施状況。

## 共通操作
- 並べ替え・絞り込み(ステータス、プロジェクト、優先度)。
- 行の選択で右パネルにタスク詳細。

## 各画面の状態
空状態(例: inboxが空なら「整理済み」表示)/ 読み込み中(スケルトン)/ エラー(再試行)。
```

## 画面と状態の網羅チェック

| 画面 | レイアウト | 通常 | 空 | 読み込み中 | エラー |
| --- | --- | --- | --- | --- | --- |
| 実行画面 | モバイル中心 | ○ | ○(今日の予定なし) | ○ | ○ |
| 実行画面: 1日の完了後の選択 | モバイル中心 | ○ | - | - | - |
| タスク詳細 | ボトムシート / サイドパネル | ○ | ○(新規) | ○ | ○(保存エラー) |
| inbox クイック追加 | 共通 | ○ | - | ○(保存中) | ○ |
| inbox整理 | デスクトップ中心 | ○ | ○ | ○ | ○ |
| 3枠割り当て | デスクトップ中心 | ○ | ○ | ○ | ○ |
| カレンダー(日・週) | デスクトップ中心 | ○ | ○ | ○ | ○ |
| プロジェクト画面 | デスクトップ中心 | ○ | ○ | ○ | ○ |
| 待ち / いつか / 習慣 一覧 | デスクトップ中心 | ○ | ○ | ○ | ○ |

全画面でライト/ダークの両テーマを作る。

## スコープ外(デザインしない)

- AI提案・AI実行の画面、MCP、スキル、グラフ、実績ログ(日記)閲覧は MVP(Phase 0〜3)の範囲外のため、このプロンプトには含めない。
- Googleカレンダーとの直接同期UI。
